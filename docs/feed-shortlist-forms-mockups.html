Where the longer lists come from DB

You asked for the lists to be built from a public source and stored in the DB. Plan: a one-time import script in apostrophe-admin (scripts/import-master-data.ts) fetches the list and upserts it into the masterData collection as LANGUAGE and DOMAIN rows. It adds missing rows and never deletes, so it's safe to re-run. The 12 domains and 13 languages already there keep their exact names, because interviewers, students and saved filters use them. The app and website keep reading /config → masterData, so nothing is hard-coded, and Admin › Master data can still edit, add or hide items.

Languages · proposed sourceISO 639-1 English names (about 180 languages) plus the 22 scheduled languages of India. ISO 639-1 alone is missing Maithili, Manipuri, Bodo, Dogri, Konkani and Santali, so those come from ISO 639-2/3. Today's 13 stay as they are.
Domains · proposed sourceUNESCO ISCED-F 2013, the international list of fields of education: 11 broad, 29 narrow and about 80 detailed fields. Each new domain stores its broad field as a group, which is the grey line under each result. Its licence is CC BY-NC-SA; check that before shipping.
Booking needs careInterviewer matching (domainMapping.ts) maps a student's field to one of today's 12 domains by keyword. A new domain with no interviewer yet means no slots for that student. So the plan: a student's new domain falls back to its broad field's interviewers. This needs the group stored on each domain (decision 3).
AdminThe Master data page lists the new rows like any other. No new screen; it may need search and paging if it doesn't have them, since the domain list grows to about 90.

Decisions before the build

My recommended answer is first in each.

1Stamp style: A white badge (same as the web) · B solid white · C white outline.
2Sign-out: centre dialog (same as the web) · bottom sheet (app only; the web keeps the centre dialog).
3Domains: import the ISCED-F detailed fields (~80) with their broad group, and let booking fall back to the broad group · import only the 29 narrow fields · hand-pick a shorter Indian list instead.
4Student "Field of study": turn it into a single-pick dropdown of domains, which also makes interviewer matching exact · keep it free text and only change Languages.
5Mass Interest limit per send (employer.interestBatchMax, admin-editable): 20 · 10 · 50 · no limit.
6Tick instead of "Verified" elsewhere: also on the profile page and the web feed/profile (drawn above) · feed card only.
7Profile pill length: no length, same as the feed (drawn) · "Watch full interview · 12:30".
