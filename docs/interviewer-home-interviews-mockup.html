Interviewer app · design options

Home and Interviews, four ways each

The interviewer persona of the native app (tabs: Home, Interviews, Availability, Wallet, Account). Everything drawn uses fields the app and its API already have today; names, times, rupee amounts and counts are placeholder-shaped samples. Pick an option in the chooser, switch the state above each screen, and tap rows, pills, tabs and buttons. Tapping an interview opens its detail screen, as it does in the app today.

PROPOSAL  Dashed tag and outline: not in the app today. Some of these use fields the server already sends but the screen does not show.
Config-driven values (join window, scorecard window, the “urgent” threshold, fees per tier) are admin settings in /config; the numbers here are samples.
No masking: the interviewer app shows the candidate’s full name everywhere (rows, room, detail). Only the student app masks the interviewer.

1 · Home

Reads GET /interviewers/me: stats, next session with its join window, scorecards owed. If the account must change its password the app redirects to the forced password screen before Home draws, so there is no Home state for it.

2 · Interviews

Reads GET /interviewers/me/interviews. Today’s app groups rows as Live, Upcoming, Owed, Past, with pills and counts. Each row opens the interview detail (drawn here as a shortened version of the real screen).
